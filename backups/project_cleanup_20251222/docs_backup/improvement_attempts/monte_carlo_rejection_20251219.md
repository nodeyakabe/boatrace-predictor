## アプローチ概要

### 理論的根拠

レース物理モデルをシミュレーションし、5000回の試行から確率分布を生成することで、より正確な順位予測を行う。

### 実装内容

| コンポーネント | 説明 |
|---------------|------|
| スタートモデル | STタイム分布からスタート位置を決定 |
| ターンモデル | コース位置、技術、乱数からターン通過順を計算 |
| 直線モデル | モーター性能、ボート性能から速度を決定 |
| レース統合 | 2周（3マーク）のシミュレーション |

### 実装ファイル

| ファイル | 説明 |
|----------|------|
| `src/simulation/race_physics.py` | 物理モデル（スタート、ターン、直線） |
| `src/simulation/race_simulator.py` | レースシミュレーター本体 |
| `scripts/quick_monte_carlo_test.py` | 検証スクリプト |

## 検証結果

### テスト条件

| 項目 | 値 |
|------|-----|
| テスト期間 | 2025-11-28 〜 2025-12-08 |
| 対象レース | 300レース |
| シミュレーション回数 | 5000回/レース |
| 統合重み | integration_weight=0.3 |

### 結果サマリ

| 指標 | Baseline | Monte Carlo | 差分 | 判定 |
|------|----------|-------------|------|------|
| 1着的中率 | 48.0% | 39.5% | **-8.5pt** | NG |
| 2着的中率 | 29.4% | 30.9% | +1.5pt | - |
| 3着的中率 | 21.0% | 18.5% | **-2.5pt** | NG |
| 3連単的中率 | 5.95% | 3.70% | **-2.25pt** | NG |
| 実行時間/レース | 929ms | 1337ms | **+407ms (+44%)** | NG |

### 詳細分析

#### 1着精度悪化の原因

- 物理モデルがインコース有利度を過小評価
- スタートタイミングの乱数が大きすぎる
- 実際のレースはスタート〜1ターンで8割決まるが、モデルはそれを反映していない

#### 2着がわずかに改善した理由

- ターンでの順位変動が現実に近い確率で発生
- ただし、1着・3着の悪化を補えるほどではない

#### 3着精度悪化の原因

- シミュレーションの分散が大きすぎる
- 確定的な要素（コース有利度、選手力差）が希釈される

#### 計算コスト増大の原因

- 5000回のシミュレーションが重い
- 各シミュレーションでターン・直線を複数回計算
- NumPy最適化の余地はあるが、根本的な改善は困難

## 不採用理由

### 1. 主要指標の悪化

| 指標 | 目標 | 結果 | 判定 |
|------|------|------|------|
| 1着的中率 | 維持以上 | **-8.5pt** | NG |
| 3着的中率 | +2pt以上 | **-2.5pt** | NG |
| 3連単的中率 | 維持以上 | **-2.25pt** | NG |

主要な3指標が全て悪化しており、採用の余地がない。

### 2. 計算コストの増大

- 処理時間が44%増加（929ms → 1337ms）
- リアルタイム予測への影響が懸念
- 効果がないのにコストだけ増加

### 3. 物理モデルの限界

- ボートレースの複雑な要素（水面状況、選手の駆け引き、事故など）をモデル化困難
- 乱数ベースのシミュレーションは安定性に欠ける
- モデルの精度向上には多大な開発工数が必要

### 4. 代替手法の優位性

ペアワイズスコアリング（アプローチ3）が全ての指標で改善を達成:
- 2着的中率: +7.3pt（モンテカルロ: +1.5pt）
- 3着的中率: +3.9pt（モンテカルロ: -2.5pt）
- 計算コスト: ほぼゼロ（モンテカルロ: +407ms）

## 教訓

### 1. 物理シミュレーションの適用限界

ボートレースのような複雑なスポーツでは、物理モデルの精度向上が困難。特に:
- 選手の心理・駆け引き
- 水面・風況の影響
- 事故・フライングリスク

これらを正確にモデル化するには、膨大なデータと開発工数が必要。

### 2. シミュレーション回数と精度のトレードオフ

5000回のシミュレーションでも安定した結果が得られなかった。回数を増やせば計算コストが増大し、減らせば分散が大きくなるジレンマ。

### 3. 既存モデルとの統合の難しさ

- integration_weight=0.3でも悪影響
- 既存モデルの予測を希釈してしまう
- 強い根拠がない限り、既存モデルを重視すべき

### 4. 早期検証の重要性

300レースでの早期検証により、本番導入前に問題を発見できた。大規模実装前の小規模テストは必須。

## 今後の方針

### モンテカルロシミュレーションについて

1. **現状維持**: 機能フラグは False のまま
2. **アーカイブ**: 実装コードは残すが、本番では使用しない
3. **再検討条件**: 物理モデルの精度が大幅に向上した場合のみ

### 代替アプローチ

ペアワイズスコアリング（アプローチ3）を採用・展開する:
- 2着・3着精度の改善に効果的
- 計算コストが低い
- 段階的に本番展開
