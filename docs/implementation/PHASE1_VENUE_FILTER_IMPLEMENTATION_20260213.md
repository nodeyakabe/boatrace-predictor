## 🛠️ 実装時の技術的課題と解決

### 課題1: venue_codeの形式不一致

**問題:**
- DBのvenue_codeは文字列（'01', '02', '05', '06'）
- venue_filterに整数[5, 6, 1, 4]を指定すると0件になる

**解決:**
```python
# venue_clauseの生成ロジックを修正
if cond.get('venue_filter'):
    venue_codes = []
    for v in cond['venue_filter']:
        if isinstance(v, int):
            venue_codes.append(f"'{v:02d}'")  # 0埋め2桁文字列に変換
        else:
            venue_codes.append(f"'{v}'")
    venue_clause = f"AND r.venue_code IN ({','.join(venue_codes)})"
```

## ⚠️ リスクと今後の課題

### リスク1: C10条件のサンプル数減少

**現状:**
- 2024年: 24件（少ない）
- 2025年: 20件（少ない）

**原因:**
- predicted_course=5（5コースからの予測1位）という厳しい条件
- 会場フィルター追加でさらに絞り込まれる

**対策:**
- 四半期ごとにサンプル数をモニタリング
- サンプル数が年間20件未満になる場合は条件見直し

### リスク2: 市場変化への対応

**現状:**
- C2条件は2021-2022年で赤字（市場調整期間と推測）
- 2023年以降は安定黒字

**対策:**
- 四半期ごとに会場別ROIを再分析
- ROI < 80%が2年連続の会場はフィルターから除外
- 年度別トレンド分析で市場変化を検知
