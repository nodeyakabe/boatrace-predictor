## 3.5 トラブルシューティング: データ欠損時の対応手順

### 概要

過去のレースデータが欠損している場合に、手動で一括取得するための手順。

### 症状

- 12月購入シミュレーションで特定日のデータが欠落
- 「要取得」「予測なし」と表示される日がある
- `bulk_scraper.py`が日付形式バグでデータ取得失敗していた

### 対応スクリプト

新規作成: `scripts/fetch_historical_data.py`

### 使用方法

```bash
# 1. 不足データの確認
python scripts/fetch_historical_data.py --start 2025-12-01 --end 2025-12-11 --check-only

# 2. 不足データの取得（予測生成も含む）
python scripts/fetch_historical_data.py --start 2025-12-02 --end 2025-12-04

# 3. 予測生成をスキップする場合
python scripts/fetch_historical_data.py --start 2025-12-02 --end 2025-12-04 --no-predict

# 4. 既存データがある日はスキップ
python scripts/fetch_historical_data.py --start 2025-12-02 --end 2025-12-04 --skip-existing

# 5. 特定会場のみ
python scripts/fetch_historical_data.py --start 2025-12-02 --end 2025-12-04 --venues 01,07,21
```

### 確認ポイント

1. **日付形式**: スクレイパーは`YYYYMMDD`形式を期待（DBは`YYYY-MM-DD`）
2. **非開催日**: 会場によっては非開催日があり、エラーになるが問題なし
3. **レート制限**: 1レースごとに0.3秒の待機を入れている

### 関連バグ修正（2025-12-11）

- `src/scraper/bulk_scraper.py:64-100` の日付形式変換を修正
- `race_date_yyyymmdd`変数を追加し、`get_race_card`にYYYYMMDD形式で渡すように変更

### なぜ効果がなかったか

これら3施策はすべて**倍率（multiplier）調整アプローチ**でした。

**根本的な問題**:
- 倍率は「予測の確信度」や「ROI（期待値）」には影響する
- しかし、**どの艇が1着と予測されるか（ランキング順位）は変わらない**
- 的中率を上げるには、**予測スコア（PRE_SCORE/BEFORE_SCORE）の計算ロジック自体を改善**する必要がある

**例**:
```
デフォルト: 1号艇 スコア100（倍率1.2） → 1着予測
最適化後:   1号艇 スコア100（倍率1.3） → やはり1着予測（順位変わらず）
```

### 唯一の副次効果

**複合パターンボーナス**のみROI +11%改善があり、期待値ベースでは収益向上が見込める。的中率は不変だが、配当期待値は向上するため、採用する価値はあるかもしれない（要検討）。

## 6. 直前情報スコアリングの詳細検証（🟡 中優先度）

**目的**: 現在の加算方式の直前情報スコアリングの法則性を再検証し、最適化の余地を探る

### 6-1. 直前情報の影響度分析

**背景**: 現在の直前情報は加算方式（pre_score × 0.6 + before_score × 0.4）だが、各要素の影響度を詳細に検証していない

**検証項目**:
1. **展示タイムの影響度**
   - ランク別（1位/2位/3位/4位/5位/6位）の勝率・2着率・3着率
   - 会場別の展示タイム信頼性（イン強会場 vs アウト強会場）
   - 潮位との相関（大潮/中潮/小潮での展示タイム信頼度）

2. **STの影響度**
   - ST範囲別（0.10以下/0.11-0.15/0.16-0.20/0.20超）の勝率
   - フライング・出遅れの影響
   - 前走STとの相関

3. **進入コースの影響度**
   - 枠なり進入 vs 枠番変更の勝率差
   - 会場別の進入変動率（大村/下関など）
   - インコース取りの成功率

4. **チルト・風の影響度**
   - チルト角度（-0.5/0/+0.5/+1.0/+1.5）の勝率
   - 追い風・向かい風の影響（風速別）
   - コース別の風影響度（1コース vs 6コース）

5. **潮位の影響度**
   - 大潮/中潮/小潮での勝率・荒れ率
   - 干潮/満潮の影響
   - 会場別の潮位感応度（住之江/尼崎など）

6. **部品交換・調整重量の影響度**
   - 部品交換ありの勝率変化
   - 調整重量の多寡による影響

**検証方法**:
- 2025年全期間（16,979レース）のデータで多変量解析
- LightGBMのfeature_importanceで要素別寄与度を算出
- 会場別・条件別のクロス集計

**成果物**:
- `docs/beforeinfo_detailed_analysis_2025.md` - 詳細分析レポート
- `scripts/analyze_beforeinfo_impact.py` - 分析スクリプト

### 6-2. 直前情報スコアリング最適化案

**検証結果を踏まえた最適化案**:
1. **要素別重み付けの見直し**
   - 現在: 展示25点、ST25点、進入20点、前走15点、チルト10点、部品5点
   - 提案: feature_importanceに基づく動的重み付け

2. **会場別スコアリング**
   - イン強会場: 展示タイム重視、ST・進入軽視
   - アウト強会場: 進入コース重視、展示タイム軽視

3. **条件別スコアリング**
   - 風速6m以上: チルト・風スコアの重み2倍
   - 大潮: 潮位スコアの追加（新規）
   - フライング・出遅れ: STスコアのペナルティ強化

**優先度**: 🟡 中（信頼度B検証完了後に実施推奨）

## 7. 信頼度C・D独自ロジックの検討（🟢 低優先度）

**目的**: 信頼度C・Dは既に戦略Aで収益化しているが、さらなる最適化の余地を探る

### 7-1. 信頼度C専用ロジック

**現状の成功例**:
- 超高配当（150倍以上）× B1級 → ROI 337.4%

**検討項目**:

   - どのような状況で信頼度Cの予測が当たりやすいか
   - 荒れやすい会場・グレードでの精度
   - 人気薄（3-6コース）の予測精度

2. **信頼度C向けフィルター**
   - 最小三連単確率閾値（TOP30%以上など）
   - オッズ範囲の細分化（150-200倍/200-300倍など）
   - 会場特性との組み合わせ

3. **買い目点数の最適化**
   - 現在: BOX買い or フォーメーション

**現状の成功例**:

   - データ充実度による階層化（80%以上/60-80%/40-60%）
   - 1着固定 vs 2着固定 vs 3着固定の使い分け
   - オッズとデータ充実度の組み合わせ最適化

3. **多層化戦略の拡張**
   - Tier 1-3に加えてTier 4（超堅実）の追加検討
