#### 4-5 詳細: 展示ST×アウトコース評価ルール追加

**起点事例（2026-05-12 びわこ12R）**:
- 5号艇 里岡右貴（A1/勝率7.01）: 展示ST=**0.09秒（最速!）**、展示タイム=6.91秒（4位）
- 現行ロジック: 「展示4位×コース5」→ `-9pt`（exhibition_low_course_outer -4pt + exhibition_low_st_normal_outer -5pt）
- advance予測（展示前）: **2位（60.2pt）→ 1-5-3を正解予測**
- before推定（展示後）: **4位（51.2pt）→ 1-3-2に変化・外れ**
- 実際の結果: **1-5-3（31.5倍）で決着** → advance予測が正解

**現行ルールの構造的問題**:
```
現行 exhibition_buff_rules.py（is_active=True）でSTを評価するルール:
  → 「展示TOP2 × ST良好(≤0.15) × インコース(1,2)」: +6pt のみ

つまり:
  コース4-6（アウト）での展示ST最速 → 評価ゼロ
  + 「展示4-6位 × コース4-6」で -4pt
  + 「展示3位以下 × コース4-6」で -5pt
  = 合計 -9pt（展示STが最速でも関係なし）
```

**調査方法（サンプル1件では判断不可・6年間統計で検証すること）**:

```sql
-- STEP 1: 展示ST最速（≤0.10秒）×アウトコース(4-6)の選手の1着率を計測
-- exhibition_data と results を結合して、ST最速×アウトコースの的中率を計算

WITH st_ranking AS (
    SELECT
        ed.race_id,
        ed.pit_number,
        ed.exhibition_time,
        ed.start_timing AS st,
        RANK() OVER (PARTITION BY ed.race_id ORDER BY ed.start_timing ASC) AS st_rank,
        RANK() OVER (PARTITION BY ed.race_id ORDER BY ed.exhibition_time ASC) AS exh_rank
    FROM exhibition_data ed
    WHERE ed.exhibition_time IS NOT NULL AND ed.start_timing IS NOT NULL
),
target AS (
    -- 展示ST≤0.10かつアウトコース(4,5,6)かつ展示タイム4位以下（ルールに引っかかるケース）
    SELECT sr.race_id, sr.pit_number, sr.st, sr.exh_rank
    FROM st_ranking sr
    JOIN races r ON sr.race_id = r.id
    WHERE sr.st <= 0.10
      AND sr.pit_number IN (4, 5, 6)
      AND sr.exh_rank >= 4
      AND strftime('%Y', r.race_date) BETWEEN '2020' AND '2025'
)
SELECT
    COUNT(*) AS total_races,
    SUM(CASE WHEN res.first_place = t.pit_number THEN 1 ELSE 0 END) AS first_place_count,
    ROUND(100.0 * SUM(CASE WHEN res.first_place = t.pit_number THEN 1 ELSE 0 END) / COUNT(*), 2) AS first_place_rate,
    -- 対照群（展示ST>0.15かつアウトコース4-6かつ展示タイム4位以下）
    -- 別クエリで比較すること
    AVG(sr.st) AS avg_st
FROM target t
JOIN results res ON t.race_id = res.race_id;

-- STEP 2: 参照ベンチマーク（アウトコース全体の1着率）
SELECT
    pit_number,
    COUNT(*) AS cnt,
    ROUND(100.0 * SUM(CASE WHEN res.first_place = e.pit_number THEN 1 ELSE 0 END) / COUNT(*), 2) AS first_rate
FROM entries e
JOIN results res ON e.race_id = res.race_id
JOIN races r ON e.race_id = r.id
WHERE e.pit_number IN (4, 5, 6)
  AND strftime('%Y', r.race_date) BETWEEN '2020' AND '2025'
GROUP BY pit_number ORDER BY pit_number;
```

**実装候補ルール（調査結果次第）**:
```python
# src/analysis/exhibition_buff_rules.py に追加予定
# 展示ST最速(≤0.10秒)×アウトコース: 統計的効果があれば追加
CompoundBuffRule(
    rule_id="exhibition_st_best_outer",
    name="展示ST最速×アウトコース",
    description="ST≤0.10秒かつコース4-6: アウトからのスタート力優位",
    conditions=[
        BuffCondition(ConditionType.START_TIMING, 'best'),  # ST≤0.10
        BuffCondition(ConditionType.COURSE, [4, 5, 6]),
    ],
    buff_value=X.X,  # 調査結果から決定
    is_active=False  # 調査完了後に True に変更
)
```

**調査結果の判定基準**:
- サンプル数 ≥ 200件かつ 1着率 ≥ 全体平均+3pt → ルール追加検討
- サンプル数 < 100件 → 統計的根拠なし・保留
- 1着率が全体平均以下 → 追加しない（現行ペナルティを維持）

#### 4-6 詳細: 展示バフ過剰減点の再キャリブレーション

**問題**: advance予測が正しい順位付けをしているのに、展示バフで順位が変わって外れるケースが存在する可能性。

**調査方法**:
```python
# advance予測1位の選手が before推定で何位になるかの分布を確認
# 特に「advance 1位 → before 2位以下に落ちたケース」の的中率を計測

# STEP 1: advance/before両方の予測がある日のデータを取得
# STEP 2: 1着（advance rank=1）がbeforeで何位になったかと、実際の1着結果を照合
# STEP 3: 「advance 1位 = before 1位」vs「advance 1位 ≠ before 1位」の1着的中率差を比較
```

**判定基準**: advance 1位 = before 1位 のケースと乖離ケースで1着的中率が逆転するなら、
展示バフのペナルティ値（現行: -4pt, -5pt）が過大の可能性 → 値を半減して再検証。

**注意**: 4-5の調査と同時に実施し、セットで判断すること（単独改変は禁止）。

## 🔰 ロジック変更の検証ルール（恒久ルール）

**予測再生成の前に必ず影響範囲をDBで確認する（Phase 0）。**

### 手順

1. **Phase 0（数秒〜1分）**: 変更が実際に何レースに影響するかをSQLで確認
2. **判断**:

| 影響率 | 判断 |
|--------|------|
| < 1% | 予測変化はほぼゼロ。全再生成不要と判断できる |
| 1〜5% | 影響中程度。1年分の部分再生成で傾向把握してから判断 |
| > 5% | 影響大。**全年度再生成 + フルバックテスト必須**（偶然を排除するには全数調査しかない） |

3. **全再生成が必要な場合**: 部分サンプル・特定期間では偶然を排除できないため、必ず全6年分を再生成してフルバックテスト（`--full`）で比較する

### 変更種別ごとのPhase 0確認クエリ例

```sql
-- 天候・気象条件が関係する変更
SELECT weather, COUNT(*) FROM race_conditions GROUP BY weather ORDER BY COUNT(*) DESC;

-- 会場フィルター変更
SELECT venue_code, COUNT(*) FROM races GROUP BY venue_code ORDER BY venue_code;

-- オッズ範囲変更（対象レースの件数確認）
SELECT COUNT(*) FROM trifecta_odds WHERE odds BETWEEN :新min AND :新max;
```

※ actual_course vs pit_number の確認クエリは「⏸️ actual_course修正の検証」タスクを参照

### ⚠️ 注意
- 再生成中に別のロジック変更を入れると予測が混在する → **再生成完了まで新規変更禁止**
- 「1日分のCSV比較」や「1年分の部分再生成」は期間選択の偶然性を排除できない
