## 概要

### 3段階検証の目的

| Tier | 目的 | 期間 | 合格基準 | 所要時間 |
|------|------|------|----------|----------|
| **Tier 1** | 簡易スクリーニング | 2年間（2024-2025） | ROI 150%+, 1/2年黒字, 50件+ | ~10秒 |
| **Tier 2** | 本格検証 | 6年間（2020-2025） | ROI 100%+, 4/6年黒字 | ~30秒 |
| **Tier 3** | 実装一致確認 | 6年間（2020-2025） | Tier 2との一致率 95%+ | ~60秒 |

### なぜ3段階が必要か？

1. **Tier 1: 無駄な作業を避ける**
   - 明らかに性能が低い条件を早期に除外
   - Tier 2（6年間）の重い処理を回避

2. **Tier 2: 長期安定性を確認**
   - 6年間のデータで本格的な性能評価
   - 年度別の黒字/赤字パターンを確認

3. **Tier 3: 実装乖離を防止**
   - バックテストと実運用コードで同じ結果が出るか検証
   - 見落としがちな実装ミスを検出

## Tier 1: 簡易テスト（2年間）

### 目的

新規条件の初期スクリーニング。2年間の直近データで高速テストを行い、明らかに性能が低い条件を除外します。

### 合格基準

- **ROI 150%以上**
- **1/2年黒字**（2024年または2025年が黒字）
- **サンプル数 50件以上**

#### 既存条件のテスト

```bash

```

```bash
python scripts/backtest/quick_condition_test.py --condition-json '{
  "id": "TEST_NEW",
```

## Tier 3: 実環境確認

### 目的

Tier 2（バックテスト）と実運用コードで同じ結果が出るかを確認します。実装ミスや設定漏れを検出するための最終チェックです。

### 合格基準

- **Tier 2との一致率 95%以上**

### 使用方法

#### 1. Tier 2結果をJSON保存（再実行）

```bash
python scripts/backtest/standard_backtest.py --full --save-json data/tier2_results.json
```

#### 2. Tier 3検証実行

```bash
python scripts/validation/verify_prediction_consistency.py \
    --start 2020-01-01 --end 2025-12-31 \
    --tier2-results data/tier2_results.json
```

### Tier 3で不合格の場合

```
[Tier 2との比較]
----------------------------------------------------------
  Tier 2購入件数: 3,200件
  Tier 3購入件数: 2,850件
  一致率:         89.06%

[合格判定]
----------------------------------------------------------
  一致率:   89.06% (基準:   95.00%以上) ❌ FAIL

  総合判定: ❌ 不合格（実装に乖離があります）

  【推奨アクション】
    1. Tier 2とTier 3のロジック差異を調査
    2. config/bet_conditions.py の条件定義を確認
    3. BetTargetEvaluator の実装を確認
    4. オッズデータ、予測データの取得方法を確認
```

#### よくある原因

1. **条件定義の不一致**
   - `config/bet_conditions.py` に条件が追加されていない
   - 条件のパラメータが異なる（オッズ範囲、会場フィルター等）

2. **オッズ取得の違い**
   - Tier 2は `trifecta_odds` テーブルから直接取得
   - Tier 3は実運用ロジック（`get_odds_data()`）を使用
   - パターンH対応が漏れている（1-2-3, 1-2-4, 1-2-5）

3. **予測データの違い**
   - `prediction_type = 'before'` の確認
   - `rank_prediction` の順序確認

4. **会場コードの型違い**
   - Tier 2: 整数（1, 2, 3, ...）
   - Tier 3: 文字列（'01', '02', '03', ...）

## トラブルシューティング

### Q1: Tier 1で異常に高いROI（300%超）が出る

**原因**: サンプル数が少ない、または特定の高額的中に偏っている

**対応**:
- サンプル数を確認（50件未満なら不合格）
- Tier 2で6年間の長期検証を実施

---

### Q2: Tier 2とTier 3で大きな乖離（一致率80%以下）

**原因**: 実装ロジックの違い

**チェックリスト**:

1. **条件がconfig/bet_conditions.pyに追加されているか？**
   ```python
   from config.bet_conditions import get_condition_by_id
   cond = get_condition_by_id('NEW_CONDITION')
   print(cond)  # Noneなら追加漏れ
   ```

2. **会場コードの型が一致しているか？**
   - Tier 2: `venue_filter: [1, 2, 3]` （整数）
   - Tier 3: `venue_code = '01', '02', '03'` （文字列）
   - 変換処理: `venue_code = int(venue_code_str)`

3. **オッズ取得ロジックが一致しているか？**
   - パターンH: 1-2-3, 1-2-4, 1-2-5の3点
   - 1点買い: 1-2-3のみ

4. **予測データの取得条件が一致しているか？**
   - `prediction_type = 'before'` を使用
   - `rank_prediction = 1, 2, 3` の順序

---

### Q3: Tier 2で6年間ROI 150%だが、2025年だけ赤字

**原因**: 過学習、または市場環境の変化

**対応**:
- 年度別の内訳を確認
- 直近2年（2024-2025）が連続赤字なら不採用を検討
- 2025年のみ赤字で、2024年は黒字なら継続観察

---

### Q4: Tier 1合格、Tier 2不合格（ROI 95%）

**原因**: 直近2年に偏った性能、長期では不安定

**対応**:
- Tier 2の基準（ROI 100%+, 4/6年黒字）を満たさない条件は不採用
- 不採用案として `docs/improvement_attempts/REJECTED_IDEAS.md` に記録

---

### Q5: 条件を削除したい

**手順**:
1. `config/bet_conditions.py` から条件を削除
2. 標準テストを再実行して全体ROIを確認

```bash
python scripts/backtest/standard_backtest.py --full
```

3. 削除理由を `docs/improvement_attempts/REJECTED_IDEAS.md` に記録

## まとめ

### 検証フローのチェックリスト

- [ ] Tier 1: 簡易テスト（2年間）実行
  - [ ] ROI 150%以上
  - [ ] 1/2年黒字
  - [ ] サンプル数 50件以上
- [ ] Tier 2: 標準テスト（6年間）実行
  - [ ] 条件を `config/bet_conditions.py` に追加
  - [ ] `standard_backtest.py --full --save-json` 実行
  - [ ] ROI 100%以上
  - [ ] 4/6年黒字
  - [ ] 累計収支プラス
- [ ] Tier 3: 実環境確認
  - [ ] `verify_prediction_consistency.py` 実行
  - [ ] Tier 2との一致率 95%以上
- [ ] 最終更新
  - [ ] Tier 2結果を `config/bet_conditions.py` に反映
  - [ ] 変更をコミット

### 重要なポイント

1. **Tier 1不合格の条件をTier 2に進めない**
   - 時間の無駄、リソースの無駄

2. **Tier 2不合格の条件を本番適用しない**
   - 長期で赤字になる可能性が高い

3. **Tier 3不合格の条件は実装を修正**
   - バックテストと実運用の乖離は致命的なバグ

4. **不採用案も記録する**
   - 同じ過ちを繰り返さない
   - `docs/improvement_attempts/REJECTED_IDEAS.md` に追記
