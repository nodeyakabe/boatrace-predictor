# 市場効率性検証から得られた知見と教訓

**作成日**: 2026-02-16
**作成者**: Claude Code
**対象**: 8施策検証（Phase 1完了、TJ-6/TJ-9/TJ-10検証完了）

---

## 📋 Executive Summary

8施策検証を通じて、**市場効率性**と**実装効果**の関係性について重要な知見を得ました。

**主要な発見:**
1. **公開情報は市場オッズに織り込まれている**（TJ-6波高、TJ-10潮位）
2. **市場効率性が有望でも実装効果は保証されない**（TJ-9展示タイム）
3. **データ品質と効果は無関係**（TJ-6, TJ-10, TJ-9すべてデータ品質★★★★★だが効果なし）
4. **係数調整の限界**（±10%では効果なし、±50%では悪化）

**成功施策**: Phase 1（会場フィルター最適化）のみ → ROI +28.2pt

---

## 🎯 知見1: 公開情報は市場オッズに織り込まれる

### 検証事例

#### TJ-6（波高フィルター）

**データ品質**: ★★★★★（充足率99.45%）
**市場効率性検証**: オッズ差-4.15%（低波高時より高波高時の方がオッズが低い）
**実装効果**: 不採用（市場織り込み済み）

**解釈**:
- 高波高時は1コース不利 → 市場オッズが低下
- 波高情報は気象庁の公開データ → 市場参加者全員がアクセス可能
- **既にオッズに反映済み → ROI改善機会なし**

#### TJ-10（潮位データ）

**データ品質**: ★★★★★（充足率100%、6.47M記録）
**市場効率性検証**: 未実施（直接実装）
**実装効果**: ROI±0.0pt（効果ゼロ、ON/OFF完全同一）

**解釈**:
- 潮位データは公開情報（気象庁、海上保安庁）
- TideAdjusterは実装済み・常時稼働中だったが、6年間効果なし
- **公開情報の補正では利益機会を作れない**

### 教訓

**公開情報ベースの施策は慎重に**:
- 気象データ（波高、風速、潮位）
- 選手データ（級別、勝率、F数）
- モーターデータ（2連率、3連率）

**実装前の確認事項**:
1. **市場効率性検証**: オッズ差≥+5%を確認
2. **データソース確認**: 非公開データか、公開データか
3. **ON/OFF比較テスト**: 実装後の効果検証

## 🎯 知見2: 市場効率性が有望でも実装効果は保証されない

### 検証事例: TJ-9（展示タイム信頼性マップ）

**市場効率性検証（Phase 0）:**
- 高信頼性会場（徳山等）: 平均オッズ90.57倍、ROI 69.26%
- 低信頼性会場（江戸川等）: 平均オッズ59.02倍、ROI 39.07%
- オッズ差: **+38.67%**（市場非効率性あり） ✅
- ROI差: **+30.19pt**（市場が会場別信頼性を正しく評価していない） ✅

**実装効果（Phase 1-2）:**

| 係数設定 | ROI | 収支 | 差分 |
|:--------|:---:|:----:|:----:|
| 係数OFF | 184.5% | +586,610円 | - |
| 係数±10% | 184.5% | +586,610円 | **±0.0pt** ❌ |
| 係数±50% | 183.3% | +581,320円 | **-1.2pt** ❌ |

**市場効率性と実装効果の乖離原因:**

1. **展示タイムは多数の要素の一つ**: 総合判定に占める割合が小さい
2. **係数調整の限界**: ±10%では順位が変わらない、±50%では過剰補正
3. **他の要素の影響が大きい**: コース、級別、モーター等の方が重要

### 教訓

**市場効率性検証だけでは不十分**:
- Phase 0（市場効率性検証）で有望でも、Phase 1（実装効果）で失敗する
- **影響度検証**が必要: 実装する要素が総合判定にどの程度影響を与えるか

**実装前の確認事項**:
1. 市場効率性検証（Phase 0）
2. **影響度検証**（Phase 0.5、新規追加推奨）
   - 実装する要素が総合スコアに占める割合
   - 係数調整による順位変動のシミュレーション
3. ON/OFF比較テスト（Phase 1）

## 🎯 知見3: データ品質と効果は無関係

### 検証事例比較

| 施策 | データ充足率 | データ品質 | 実装効果 |
|:-----|:-----------:|:----------:|:-------:|
| **TJ-10（潮位）** | **100%**（7会場） | ★★★★★ | ROI±0.0pt ❌ |
| **TJ-6（波高）** | **99.45%**（24会場） | ★★★★★ | オッズ差-4.15% ❌ |
| **TJ-9（展示タイム）** | **98.48%**（24会場） | ★★★★★ | ROI±0.0pt～-1.2pt ❌ |

**すべて高品質データだが、効果ゼロまたは悪化**

### 教訓

**データ品質が良い ≠ 効果がある**:
- データが揃っていても、市場効率性が高ければ効果なし
- データが完璧でも、実装方法が不適切なら効果なし

**重要なのは**:
1. **市場効率性**: 市場がその情報を織り込んでいないか
2. **実装設計**: データをどう活用するか（係数調整か、フィルターか、新規特徴量か）

## 🎯 知見4: 係数調整の限界

### 検証事例: TJ-9（展示タイム信頼性マップ）

**係数パターン1（控えめ）: ±10%**
- 高信頼性会場: 係数1.10（+10%）
- 低信頼性会場: 係数0.90（-10%）
- **結果**: ROI±0.0pt（完全に同一の結果）

**係数パターン2（強化版）: ±50%**
- 高信頼性会場: 係数1.50（+50%）
- 低信頼性会場: 係数0.50（-50%）
- **結果**: ROI-1.2pt（悪化）

### 失敗の原因

**展示タイムスコアの構造:**
- 展示タイムスコア: 最大10点（総合スコアの約5-10%）
- 総合スコア: 100-150点程度
- **±10%の補正**: 最大±1点程度 → 順位に影響しない
- **±50%の補正**: 最大±5点程度 → 過剰補正により誤判定が増加

### 教訓

**スコアの一部要素への係数調整は効果が出にくい**:
- 総合スコアに占める割合が小さい要素への係数調整は無意味
- 係数を強化すると過剰補正により悪化する

**有効なアプローチ**:
1. **フィルター方式**: 条件を満たさないレースを除外（Phase 1の成功例）
2. **新規特徴量**: 独立した評価軸を追加
3. **重み調整**: 総合スコアの計算式を見直す

**避けるべきアプローチ**:
- ❌ 既存スコアへの係数調整（±10-50%程度）
- ❌ 複雑なボーナスシステム（ExhibitionScorerV3の失敗事例）

## 🎯 知見5: シンプルで直接的な施策が最も効果的

### 成功事例: Phase 1（会場フィルター最適化）

**実装内容**: venue_filterパラメータ追加のみ
**実装時間**: 15分
**効果**: ROI +28.2pt

**成功要因**:
1. **シンプル**: venue_filterに会場コードを追加するだけ
2. **直接的**: 会場別ROIが明確、フィルター効果が即座に分かる
3. **データが確実**: 6年間の実績で検証済み、各会場のROIが明確

### 失敗事例: TJ-9（展示タイム信頼性マップ）

**実装内容**: 会場別係数マップ、ExtendedScorer修正、機能フラグ追加
**実装時間**: 90分
**効果**: ROI±0.0pt～-1.2pt（悪化）

**失敗要因**:
1. **複雑**: 3ファイル修正、係数マップ定義、機能フラグ追加
2. **間接的**: 展示タイムスコアに係数を掛けて総合スコアに反映（間接的）
3. **効果が不明確**: 市場効率性検証では有望だが、実装効果は未知数

### 教訓

**シンプル・イズ・ベスト**:
- 実装がシンプルで、効果が直接的な施策を優先
- 複雑な実装は、失敗リスクが高く、メンテナンスコストも高い

**施策の優先順位**:
1. **Tier 1**: シンプル、直接的、データ確実（Phase 1型）
2. **Tier 2**: やや複雑、間接的、データ品質良好（TJ-9型）
3. **Tier 3**: 複雑、間接的、データ不足（TJ-8型）

## 🎯 実装前チェックリスト（推奨）

新規施策を実装する前に、以下を確認することを推奨します。

### Phase 0: 市場効率性検証（必須）

- [ ] データソースは公開か非公開か確認
- [ ] 市場効率性検証スクリプトを作成・実行
- [ ] オッズ差≥+5%を確認（基準未達なら不採用）
- [ ] サンプル数≥100件を確認（統計的有意性）

### Phase 0.5: 影響度検証（推奨、新規追加）

- [ ] 実装する要素が総合スコアに占める割合を確認
- [ ] 係数調整の場合、順位変動のシミュレーションを実施
- [ ] 影響度が小さい場合（<5%）、実装方法を再検討

### Phase 1: 実装・ON/OFF比較（必須）

- [ ] 機能フラグで制御可能にする
- [ ] ON/OFF両パターンでバックテストを実行
- [ ] ROI差≥+1pt、収支プラスを確認
- [ ] 黒字年数6/6年を維持

### Phase 2: 採用判定（必須）

- [ ] ROI≥+1pt（最低基準）
- [ ] 収支プラス
- [ ] 黒字年数維持
- [ ] 実装複雑度が効果に見合うか確認

## 📚 まとめ

8施策検証を通じて、以下の重要な知見を得ました。

**成功の鍵**:
1. ✅ **シンプルで直接的な施策**（Phase 1型）
2. ✅ **市場非効率性の活用**（非公開データ、独自指標）
3. ✅ **実装前の多段階検証**（Phase 0 → 0.5 → 1 → 2）

**失敗の原因**:
1. ❌ **公開情報への依存**（市場織り込み済み）
2. ❌ **係数調整への過度な期待**（影響度が小さい）
3. ❌ **市場効率性検証のみ**（実装効果を保証しない）

**今後の方向性**:
- ✅ Phase 1（会場フィルター）の継続モニタリング
- ✅ 非公開データ、独自指標の探索
- ✅ シンプルで直接的な施策を優先
- ❌ 公開情報ベースの施策は慎重に検証
