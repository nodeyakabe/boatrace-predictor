# スケジューラ使用ガイド

## 概要

`daily_scheduler.py` は、ボートレース予想システムの自動化スクリプトです。
毎朝のデータ収集・予想生成・レース通知を自動で実行します。

## 実装された二重起動防止機能

### 機能概要

- **ロックファイル方式**: `data/daily_scheduler.lock` を使用
- **PIDチェック**: 既存プロセスが生きているか確認
- **自動クリーンアップ**: 終了したプロセスのロックファイルは自動削除

### 動作

1. 起動時に `data/daily_scheduler.lock` の存在をチェック
2. ロックファイルが存在する場合:
   - 記録されたPIDのプロセスが生きているか確認
   - 生きている場合: エラーメッセージを表示して終了
   - 死んでいる場合: 古いロックファイルを削除して起動
3. 新しいロックファイルを作成（現在のPIDを記録）
4. 終了時にロックファイルを自動削除

## 使い方

### 起動

```bash
python scripts/automation/daily_scheduler.py
```

### 停止

- `Ctrl+C` で正常終了（ロックファイルも自動削除）
- または別ターミナルから:
  ```bash
  taskkill //F //PID <プロセスID>
  ```

### 二重起動を試みた場合

```
[ERROR] daily_schedulerは既に起動しています (PID: 12345)
[ERROR] 既存のプロセスを停止してから再実行してください

[ERROR] 既に起動中のため終了します
```

このエラーメッセージが表示されます。

## スケジュール

- **毎朝 7:00** - 前日のレース結果収集
- **毎朝 7:30** - 前日の直前情報収集
- **毎朝 7:45** - 前日の直前予想生成
- **毎朝 8:00** - 前日のオリジナル展示データ収集
- **毎朝 8:15** - 本日のオッズ収集
- **毎朝 8:30** - 本日の予想生成 + ディスコード通知
- **各レース締切10分前** - 直前情報取得・通知（動的スケジュール）

## トラブルシューティング

### ロックファイルが残っている場合

プロセスが異常終了した場合、ロックファイルが残ることがあります。
以下のコマンドで手動削除できます:

```bash
# Windows
del data\daily_scheduler.lock

# Linux/Mac
rm data/daily_scheduler.lock
```

### プロセスIDの確認

```bash
# Windows PowerShell
Get-CimInstance -ClassName Win32_Process -Filter "Name='python.exe'" | Where-Object {$_.CommandLine -like '*daily_scheduler*'}

# Linux/Mac
ps aux | grep daily_scheduler
```

## 必要なパッケージ

- `schedule` - スケジュール管理
- `psutil` - プロセス管理（二重起動防止）
- `requests` - Discord通知
- `python-dotenv` - 環境変数読み込み

インストール:
```bash
pip install -r requirements.txt
```

または個別に:
```bash
pip install schedule psutil requests python-dotenv
```

## ディスコード通知

以下の通知が送信されます:

1. **起動通知** - スケジューラ起動時
2. **予想生成完了通知** - 毎朝8:30（購入対象レース一覧付き）
3. **レース通知** - 各レース締切10分前
4. **停止通知** - スケジューラ停止時
5. **エラー通知** - エラー発生時

## 前日データ収集について（2026-01-22追加）

### なぜ前日のデータを収集するのか

**レース結果とオリジナル展示は、確定後のデータのみ取得可能**なため、前日のデータを翌朝に収集します。

| データ種別 | 収集タイミング | 理由 |
|-----------|---------------|------|
| **レース結果** | 翌朝7:00 | レース終了後に確定するため |
| **直前情報** | 翌朝7:30 | 直前情報確定後、前日分のみ取得可能 |
| **前日直前予想** | 翌朝7:45 | 前日の直前情報を使って予想生成 |
| **オリジナル展示** | 翌朝8:00 | 展示走行後に確定、前日分のみ取得可能 |
| **オッズ** | 当日8:15 | 当日の最新オッズを取得 |
| **当日事前予想** | 当日8:30 | 当日データで生成 |

### レース結果収集（毎朝7:00）

1. 前日の日付を計算
2. 前日のレース一覧を取得
3. 結果が未保存のレースのみを対象に収集
4. 既に結果が保存済みのレースはスキップ

### 直前情報収集（毎朝7:30）

1. 前日の日付を計算
2. 前日のレース一覧を取得
3. 直前情報（展示タイム、ST、チルト角度等）を収集
4. race_detailsテーブルに保存

### 前日直前予想生成（毎朝7:45）

1. 前日の日付を計算
2. 前日のレース一覧を取得
3. 直前情報があるレースを対象に直前予想を生成
4. race_predictionsテーブルに保存（prediction_type = 'before'）

### オリジナル展示収集（毎朝8:00）

1. 前日の日付を計算
2. 全24場 × 12Rを対象に収集
3. オリジナル展示は**前日分のみ取得可能**（当日取得不可）
4. 一度逃すと永久欠損するため、毎日実行が必須

### 通知が2通来る問題の原因

スクリプトが2回起動していると、すべての通知が2通送信されます。
**二重起動防止機能により、この問題は自動的に防止されます。**

## 注意事項

- スケジューラは常駐プロセスとして動作します
- システム再起動時は手動で再起動が必要です
- Windowsタスクスケジューラやsystemd等で自動起動設定を推奨
