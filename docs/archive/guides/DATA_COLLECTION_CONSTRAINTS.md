**よくある間違い**:
- ❌ 「オリジナル展示は過去データも取得できる」と思い込む

## ⚠️ 重要な制約 TOP 3

### 1. オリジナル展示データの時間制約（最重要）

**最重要**: オリジナル展示は**昨日までのデータしか収集できない**

```
✅ 前日のレース: 取得可能
   例: 1月15日に1月14日のデータを取得

❌ 当日以前の過去レース: データ削除済み（会場による）
   例: 1月15日に1月13日以前のデータを取得しようとする

❌ 未来のレース: データ未公開
   例: 1月15日に1月16日のデータを取得しようとする
```

**運用への影響**:
1. **毎日の自動収集が必須** - 一度逃すと二度と取得できない
2. **過去データの補完は不可能** - 欠損したら永久に欠損
3. **最適な収集タイミング**: 前日夜23:00に翌日分のデータを収集

**理由**: Boatersサイトは直前情報のため、前日分のみ公開

**詳細**: [docs/knowledge/オリジナル展示収集_知見とトラブルシューティング.md](../knowledge/オリジナル展示収集_知見とトラブルシューティング.md)

---

### 2. 公式データは数年前も公開されている（重要）

**重要**: 公式API（レース基本情報、結果、オッズ等）は**過去数年分のデータが常時公開**

```
✅ 過去データ取得可能:
- レース基本情報（races, entries）
- レース結果（results）
- 払戻金（payouts）
- オッズ（trifecta_odds, exacta_odds）
- レース条件（race_conditions）
- 直前情報（beforeinfo: 展示タイム、チルト、部品交換、気象）

期間: 2020年以降のデータは常時取得可能
```

**Claude Codeへの注意**:
- ✅ 「過去データも取得可能」が正しい
- ❌ 「公式APIは最新データのみ」は誤解
- ✅ 過去の補完は通常問題なく実行可能
- ❌ 「過去データは取れない」と判断しない

**例外**: オリジナル展示のみ時間制約あり（上記参照）

**実例**:
```bash
# 2020年のデータも問題なく取得可能
python scripts/data_collection/fetch_historical_data_parallel.py \
  --start 2020-01-01 \
  --end 2020-12-31
```

### 3. データベーススキーマの正確な理解

**よくある間違い**: カラム名を誤解して使用

#### 間違い例A: `date` vs `race_date`

```python
# ❌ 間違い
WHERE date = ?

# ✅ 正しい
WHERE race_date = ?
```

**正しいスキーマ**:
```sql
CREATE TABLE races (
    id INTEGER PRIMARY KEY,
    venue_code TEXT,
    race_date TEXT,    -- ❌ "date"ではない
    race_number INTEGER,
    ...
);
```

#### 間違い例B: `waku` vs `pit_number`

```python
# ❌ 間違い
WHERE waku = ?

# ✅ 正しい
WHERE pit_number = ?
```

**正しいスキーマ**:
```sql
CREATE TABLE race_details (
    id INTEGER PRIMARY KEY,
    race_id INTEGER,
    pit_number INTEGER,  -- ❌ "waku"ではない
    chikusen_time REAL,
    ...
);
```

**参照**: [docs/architecture/DATABASE_SCHEMA.md](../architecture/DATABASE_SCHEMA.md)

## 🚨 Claude Codeへの重要な注意事項

### ✅ 正しい認識

1. **公式データ（レース・結果・オッズ）は過去数年分取得可能**
   - 「過去データは取れない」と判断しない
   - 補完スクリプトは通常問題なく実行可能

2. **オリジナル展示のみ前日限定**
   - 毎日の自動収集が必須
   - 過去データの補完は不可能

3. **データベーススキーマは正確に把握**
   - `date` ではなく `race_date`
   - `waku` ではなく `pit_number`

---

### ❌ よくある間違い

1. **「公式APIは最新データのみ」と誤解**
   - 実際は2020年以降のデータが常時公開
   - 過去の補完は問題なく可能

2. **「オリジナル展示も過去データ取得可能」と思い込む**
   - 実際は前日分のみ
   - 一度逃すと永久に欠損

3. **「データベースのカラム名を推測」**
   - 必ずスキーマを確認
   - `date` や `waku` は存在しない

## 📝 実務での対応

### シナリオ1: 「過去のレースデータを補完して」

**ユーザーからの依頼**:
> 2022年のデータが欠けているので補完してください

**正しい対応**:
```bash
# ✅ 公式データは過去も取得可能
python scripts/data_collection/fetch_historical_data_parallel.py \
  --start 2022-01-01 \
  --end 2022-12-31
```

**間違った対応**:
> ❌ 「公式APIは最新データのみなので、過去データは取得できません」

---

### シナリオ2: 「オリジナル展示データを補完して」

**ユーザーからの依頼**:
> 2024年のオリジナル展示データが欠けているので補完してください

**正しい対応**:
> ⚠️ オリジナル展示は前日分のみ取得可能です。2024年のデータは既に削除されているため、補完は不可能です。今後は毎日自動収集を実行することで、データ欠損を防ぐことができます。

**間違った対応**:
> ❌ 「過去データも取得可能です。スクリプトを実行します」

---

### シナリオ3: 「決まり手データを補完して」

**ユーザーからの依頼**:
> 決まり手データが抜けているので補完してください

**正しい対応**:
```bash
# ✅ 決まり手は公式データなので過去も取得可能
python scripts/data_collection/補完_決まり手データ_改善版.py
```

**間違った対応**:
> ❌ 「決まり手データは過去分取得できません」

## 🔧 トラブルシューティング

### Q1: 「過去データが取得できない」エラー

**原因1**: オリジナル展示を取得しようとしている
- **対処**: オリジナル展示は前日分のみ。他のデータ（レース・結果・オッズ）は過去も取得可能

**原因2**: スクリプトのバグ
- **対処**: 推奨スクリプトを使用しているか確認

**原因3**: ネットワークエラー
- **対処**: リトライまたは期間を短く分割

---

### Q2: 「カラムが見つかりません」エラー

**症状**:
```
sqlite3.OperationalError: no such column: date
sqlite3.OperationalError: table race_details has no column named waku
```

**原因**: カラム名の誤解

**対処**:
- `date` → `race_date`
- `waku` → `pit_number`

**参照**: [docs/knowledge/オリジナル展示収集_知見とトラブルシューティング.md](../knowledge/オリジナル展示収集_知見とトラブルシューティング.md)

---

### Q3: 「オリジナル展示が取得できない」

**原因1**: 前日以外の日付を指定している
- **対処**: 前日の日付を指定

**原因2**: Boatersサイトで非公開の会場
- **対処**: SKIPリストに追加、または会場公式HPから取得

**原因3**: レート制限
- **対処**: 2並列 + 0.5秒遅延 + 20秒タイムアウト
