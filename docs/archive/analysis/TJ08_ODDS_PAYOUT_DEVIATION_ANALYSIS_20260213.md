## III. バックテスト精度への影響分析

### 1. 現在のバックテストが使用しているデータ

#### 確認結果

**結論**: ✅ **現在のバックテストはtrifecta_odds（事前オッズ）ベース**

**理論的評価**: これは**正しい方式**

- バックテストの目的は「購入時に利用可能な情報で判断した場合の成績」を評価すること

**解釈**:
- 払戻金ベースROIがやや高い（+0.6pt）
- しかし実運用では事前オッズしか利用できないため、払戻金ベースROIは参考値

## IV. オッズ歪み活用の提案

### 1. オッズ帯別補正ロジック（推奨実装）

#### 補正係数の定義

```python
# config/settings.py に追加
ODDS_BAND_CORRECTION_FACTORS = {
    # 低オッズ帯（<10倍）: 安定、補正不要
    'low': {
        'min_odds': 0,
        'max_odds': 10,
        'correction_factor': 1.0,  # 補正なし
    },

    # 中オッズ帯（10-50倍）: 軽度の変動、若干保守的に
    'medium': {
        'min_odds': 10,
        'max_odds': 50,
        'correction_factor': 0.98,  # -2% 補正
    },

    # 高オッズ帯（50-100倍）: 変動大、保守的に
    'high': {
        'min_odds': 50,
        'max_odds': 100,
        'correction_factor': 0.95,  # -5% 補正
    },

    # 超高オッズ帯（100倍+）: 変動著しい、さらに保守的に
    'very_high': {
        'min_odds': 100,
        'max_odds': float('inf'),
        'correction_factor': 0.90,  # -10% 補正
    },
}
```

#### 実装箇所

**ファイル**: `src/betting/bet_target_evaluator.py`

```python
def _apply_odds_correction(self, odds: float) -> float:
    """
    オッズ帯別補正を適用

    Args:
        odds: 事前オッズ

    Returns:
        補正後のオッズ
    """
    from config.settings import ODDS_BAND_CORRECTION_FACTORS

    for band, config in ODDS_BAND_CORRECTION_FACTORS.items():
        if config['min_odds'] <= odds < config['max_odds']:
            return odds * config['correction_factor']

    return odds  # デフォルト: 補正なし
```

## V. データ制約と限界

### 1. payouts充足率の問題

| 年度 | 充足率 | 分析可能性 |
|:----:|:-----:|:---------:|
| 2020 | 34% | ❌ 制限的 |
| 2021 | 33% | ❌ 制限的 |
| 2022 | **99%** | ✅ 優秀 |
| 2023 | 32% | ❌ 制限的 |
| 2024 | 41% | ⚠️ やや制限的 |
| 2025 | 69% | △ 改善中 |

**⚠️ 重要**:
- 2022年のみ例外的に高い充足率（理由不明）
- 2020, 2021, 2023年は約30%のみで、6年間バックテストの信頼性に制約
- 今後のデータ収集（2026年以降）で充足率向上が必要

### 2. 分析サンプルの限定性

| 項目 | 値 | 評価 |
|------|:--:|:----:|
| **総分析レース数** | 5,729 | ⚠️ 制限的 |
| **予測データとの結合可能数** | 5,729 | |
| **理想的なサンプル数** | 15,000+ | |
| **達成率** | 38% | ⚠️ やや不十分 |

**影響**:
- 会場別×オッズ帯別の詳細分析が困難
- 統計的有意性が一部の条件で確保できない
- 長期トレンドの把握が制限される

### 3. 時系列問題

**過去データ（2020-2024）**:
- payoutsがほぼ存在しない（平均35%）
- 歴史的傾向の分析が不可能
- バックテスト精度の検証が制限される

**現在データ（2025年）**:
- payouts充足率69%で改善中
- アクティブな分析が可能

**今後の方針**:
- 2026年以降のデータ収集を強化
- payouts充足率90%以上を目標

## VII. まとめ

### 重要な発見

1. ✅ **現在のバックテスト方式は理論的に正しい**
   - trifecta_odds（事前オッズ）ベースでROI計算
   - 払戻金は事後的なデータで予測性なし

2. ⚠️ **高オッズ帯でのリスク認識が必須**
   - バックテストの-2～-5pt下振れは実運用の可能性
   - 特に江戸川（venue 04）、鳴門（venue 14）での高オッズは慎重に

3. ⚠️ **データの時系列問題**
   - 過去データ（2020-2024）はpayoutsがほぼ存在しない（平均35%）
   - 検証は2025年以降のアクティブデータのみ可能

4. ✅ **低オッズ条件は安定**
   - ±1%以内の歪みで予測可能
   - A×A1×10-12倍等の低オッズ条件は信頼性高い

### 期待される効果

| 指標 | 現状 | 改善後（推定） | 差分 |
|------|:----:|:-------------:|:----:|
| **全体ROI** | 163.9% | **164-166%** | **+0-2pt** |
| **高オッズ条件ROI** | 183.6% | **181-184%** | **-2～+0.4pt** |

**注**: 当初想定の"+2-5pt"は、データ制約を考慮すると過大評価。現実的には"+0～+2pt"。
