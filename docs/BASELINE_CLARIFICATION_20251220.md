# ベースライン数値の明確化

**作成日**: 2025-12-20
**重要度**: 高（今後の検証で誤解を防ぐため必読）

---

## 1. 問題の発生

2025年12月20日の検証で、ドキュメント記載の基準値とバックテスト結果に大きな乖離が発生。

| 指標 | ドキュメント記載 | 実バックテスト結果 | 乖離 |
|------|-----------------|-------------------|------|
| 購入件数 | 830件 | 620件 | -210件 |
| 的中数 | 36件 | 22件 | -14件 |
| ROI | 167.0% | 118.8% | -48.2pt |
| 収支 | +166,860円 | +34,920円 | -131,940円 |

---

## 2. 原因の特定

### 2.1 ドキュメントの数値は「理論値」

`docs/ALL_CONDITIONS_MATRIX_2025.md` で定義された戦略Bの5条件を**個別に分析した結果の単純合計**:

| 条件 | 購入数 | 的中数 | ROI | 収支 |
|------|--------|--------|-----|------|
| C x B1 x 30-40倍 | 299 | 15 | 158.6% | +52,560円 |
| D x A1 x 40-50倍 | 53 | 1 | 405.8% | +48,630円 |
| C x A1 x 30-40倍 | 193 | 8 | 141.7% | +24,120円 |
| D x A2 x 20-30倍 | 105 | 7 | 173.3% | +23,100円 |
| D x B1 x 40-50倍 | 183 | 5 | 132.0% | +17,550円 |
| **単純合計** | **833** | **36** | **149.7%** | **+165,960円** |

### 2.2 実バックテストとの差異の理由

1. **条件の重複**: 同一レースが複数条件にマッチする場合、単純合計では重複カウントされるが、実際は1回しか購入しない
2. **オッズ欠損**: 一部レースでオッズが取得できず除外される
3. **フィルター適用**: `bet_target_evaluator`の追加フィルター（会場×風速など）で除外されるレースがある

### 2.3 正しいベースライン

**実バックテスト結果（2025年1-11月）が正しい基準値**:

| 指標 | 正しい値 | 備考 |
|------|---------|------|
| 購入件数 | **620件** | 重複排除後 |
| 的中数 | **22件** | - |
| 的中率 | **3.55%** | 22/620 |
| 投資額 | **186,000円** | 300円×620件 |
| 払戻額 | **220,920円** | - |
| 収支 | **+34,920円** | - |
| ROI | **118.8%** | 220,920/186,000 |

## 3. 今後の対応

### 3.1 バックテスト実行時の注意

- **常に `backtest_course_enforcement_effect.py` または同等スクリプトで実測**すること
- 条件マトリクス分析の数値は参考値として扱い、実績値と混同しない
- 新機能追加後は必ず実バックテストで効果を検証

### 3.2 ドキュメント記載ルール

| 数値タイプ | 記載方法 | 例 |
|----------|---------|-----|
| **理論値** | 「理論値」「期待値」「条件分析」と明記 | ROI 149.7%（理論値・条件単純合計） |
| **実測値** | 「バックテスト結果」「実績」と明記 | ROI 118.8%（2025年1-11月バックテスト） |

### 3.3 基準スクリプト

ベースライン測定に使用する公式スクリプト:

```bash
# ベースライン測定（推奨）
python scripts/backtest_course_enforcement_effect.py

# または
python scripts/verify_order_change_effect.py
```

## 5. 教訓

1. **条件分析と実バックテストは別物** - 条件を個別分析した結果の合計は、実運用での結果と一致しない
2. **重複排除の影響は大きい** - 833件→620件（約25%減）、36件→22件（約40%減）
3. **バックテスト結果を正とする** - 理論値はあくまで参考
