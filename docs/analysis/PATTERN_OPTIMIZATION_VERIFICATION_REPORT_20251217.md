## 6. 問題点の特定

### 6.1 主要な問題: ネガティブパターンの過剰適用

ネガティブパターン（特に`pre1_st4_6`、`pre1_st5_6`）が**PRE1位の艇を過剰にブロック**している。

- `pre1_st4_6`: 659回適用のうち294回（44.6%）が実際に1着
- `pre1_st5_6`: 541回適用のうち220回（40.7%）が実際に1着

### 6.2 二次的問題: ポジティブパターンの精度不足

- `pre1_3_st1`（39.07%）、`st1_2_ex1_2_double_top`（31.93%）は適用範囲が広すぎる
- これらのパターンによるスコアブーストが正確でない予測を上位に押し上げている

### 6.3 会場特性の未考慮

- イン強会場ではSTが多少遅くても1コースが有利
- 現在のネガティブパターンは会場特性を考慮していない

### 7.2 会場別最適化の導入

# 提案: イン強会場ではネガティブパターンを緩和
IN_STRONG_VENUES = ['12', '09', '20', '18', '24']  # 住之江, 津, 若松, 徳山, 大村

def apply_negative_pattern(venue_code, multiplier):

        # イン強会場ではネガティブパターンを50%緩和

    return multiplier

## 8. 結論

### 8.1 総合評価

現在の実装は**統計的に有意に悪化**しており、即座の修正が必要です。

主な原因は:
1. ネガティブパターン（特に`pre1_st4_6`、`pre1_st5_6`）の過剰ブロック
2. 会場特性を考慮していないこと
3. ポジティブパターンの適用範囲が広すぎること

### 8.2 次のステップ

1. **緊急対応**: `pre1_st4_6`を無効化、`pre1_st5_6`を緩和
2. **短期対応**: 会場別最適化の導入
3. **中期対応**: パターン条件の厳格化とA/Bテストによる検証

### 8.3 期待される効果

上記修正により、旧ロジックと同等以上の的中率（52%以上）への回復が見込まれます。
