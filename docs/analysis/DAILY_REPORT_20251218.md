## 実施した改善策

### 1. オッズ校正機能の実装

#### 概要
- 三連単オッズから市場確率を逆算し、モデル予測と統合
- Edge検出（モデル確率 / 市場確率）によるスコア補正

#### 実装内容
- **ファイル**: `src/analysis/scorers/odds_calibrator.py`
- **クラス**: `OddsCalibrator`
  - `calibrate_predictions()`: 1着オッズ校正
  - `calibrate_rank23_predictions()`: 2着・3着オッズ校正
  - `get_optimal_trifecta_combinations()`: 期待値ベース三連単組み合わせ

#### パラメータ
- **α値**: 0.5（校正強度、0.3から調整）
- **温度パラメータ**: 4.0（Softmax、10.0から調整）
- **補正範囲**: 0.7～1.6倍（0.5～1.5倍から拡大）
- **rank23_alpha**: 0.3（2着・3着統合の重み）

### 2. 予測パイプラインへの統合

#### 統合箇所
- **ファイル**: `src/analysis/race_predictor.py`
- **行番号**: 947-950
- **処理フロー**:
  1. 確率キャリブレーション
  2. 1着オッズ校正（機能フラグで制御）
  3. スコアソート
  4. **2着・3着オッズ校正**（新規追加）← ここ
  5. 三連対スコア計算
  6. 最終ソート

### 3. 機能フラグの設定

#### 追加したフラグ
- `odds_calibration`: False（1着のみ、効果なし、保留中）
- `rank23_odds_calibration`: **True**（2着・3着、本番投入）

#### リスク評価
- **リスクレベル**: 低
- **主なリスク**: オッズデータ欠損時の処理、2着・3着順位の変動
- **緩和策**: オッズなし時は自動スキップ、alpha=0.3で緩やかな統合
- **有効化日**: 2025-12-18

| T=4.0, α=0.5 | 50 | 62.00% | 62.00% | ±0.00pt | ❌ 効果なし |

**結論**: 1着予測は市場効率が高く、オッズ校正の効果なし → 保留

### Phase 2: 上位AI（Opus）による分析

**依頼内容**:
- 効果が出ない原因の深堀り
- 2着・3着予測への適用可能性の検討
- パラメータ最適化の提案

**分析結果**:
1. **1着予測の限界**
   - 市場効率が高く、オッズに情報が織り込み済み
   - 温度T=10.0で確率分布が過度に平坦化
   - α=0.3の補正が控えめすぎる

2. **2着・3着の優位性**
   - 市場効率が低く、モデルが優位を発揮できる
   - 三連単の組み合わせ数が多く、オッズの歪みが発生
   - **期待効果: +2.0pt**

3. **推奨アクション**: **B + C 複合アプローチ**
   - 2着・3着予測への適用（優先度1）
   - 大規模データでの検証（優先度2）

### Phase 3: 2着・3着オッズ校正の検証

| 検証 | レース数 | 三連単的中率（ベースライン） | 三連単的中率（オッズ統合） | 差分 | 判定 |

**詳細結果**:

- オッズ統合: 14.29% (7/49)

- 1着的中率: 変化なし（期待通り）

**判定**: [GOOD] 改善効果あり → 2着・3着オッズ統合は有効

## 技術的知見

### 1着 vs 2着・3着の市場効率

| 順位 | 市場効率 | モデル優位性 | オッズ校正効果 | 理由 |
|------|---------|-------------|---------------|------|
| 1着 | **高い** | 低い | 効果なし | 市場参加者が最も注目、情報織り込み済み |
| 2着 | 中程度 | 中程度 | **期待大** | 注目度低下、モデルが優位を持てる |
| 3着 | **低い** | **高い** | **期待大** | 組み合わせ数多、オッズの歪み発生 |

### Softmax温度パラメータの重要性

**問題**: 温度T=10.0では確率分布が平坦化しすぎる

```python
# スコア 80, 75, 70, 65, 60, 55 の場合

# T=10.0（修正前）
艇1: 17.9%  # 差が小さすぎる
艇2: 17.3%
艇3: 16.7%

# T=4.0（修正後）
艇1: 29.5%  # 意味のある差
艇2: 22.0%
艇3: 16.4%
```

**教訓**: Softmax温度はEdge検出の精度に直結する

### 2着・3着オッズ校正の仕組み

1. **条件付き確率の計算**
   - 三連単オッズから「1着が決まった後の2着確率」を逆算
   - 例: 1-2-3のオッズ、1-3-2のオッズから2着・3着の確率を推定

2. **機械学習予測との統合**
   - `統合確率 = α × 市場確率 + (1 - α) × ML予測確率`
   - α=0.3 で緩やかな統合

3. **スコア再調整**
   - 統合確率に基づいて順位を更新
   - 2着・3着の順位変更により三連単的中率が向上

## 失敗事例と教訓

### 失敗1: 検証ロジックのミスマッチ

**問題**:
- 当初、Opusの推奨で「パターン分離」を実装
- 期待効果+2.27~3.77pt → 実測+0.18pt
- 原因: 検証用「該当レースのみ」vs 本番「全レース」の差異

**教訓**:
- 検証は必ず本番実装のコードを直接使用
- 検証スクリプトテンプレートを作成済み
- AIレビュー時は必ず本番コードを提供

### 失敗2: 温度パラメータの初期設定ミス

**問題**:
- T=10.0で補正が極端（1.5倍上限を超過）
- 1号艇: 75 → 110（1.47倍）
- 2・3号艇: 68/62 → 34/31（0.5倍）

**教訓**:
- パラメータの初期値は実データで必ずテスト
- Softmax温度は確率分布の形状を大きく変える

### 検証内容

- RacePredictorを1回だけ初期化（高速化）
- feature_flagを動的に切り替え
- 100レース検証

### 結果

| データセット | レース数 | ベースライン | オッズ校正 | 差分 | 判定 |
|--------------|----------|--------------|------------|------|------|

### 結論: 不採用

**理由**:
1. **モデルドリフト**: 2024年で有効だった手法が2025年で効果消失
2. **市場環境変化**: 2着・3着ベッティング市場の効率化
3. **追加複雑性**: 効果がない状態で複雑性だけが残る

### 対応

1. **機能フラグ無効化**
   ```python
   # config/feature_flags.py
   'rank23_odds_calibration': False  # 2025年データで効果なし
   ```

2. **不採用ドキュメント作成**
   - [`docs/improvement_attempts/rank23_odds_calibration_rejection_20251218.md`](improvement_attempts/rank23_odds_calibration_rejection_20251218.md)
   - 詳細な検証結果、不採用理由、教訓を記録
   - 同様のアプローチを再検討しないよう注意喚起

### 教訓

1. **年度別検証の重要性**: 過去データだけでなく最新データでも必ず検証
2. **効果の持続性確認**: 導入後も定期的に効果測定が必要
3. **モデルドリフト対策**: 市場環境変化への適応策が必要
